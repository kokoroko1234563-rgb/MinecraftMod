# Notebook content spec (for writers)

The Mathematician's Notebook is a Modonomicon book generated by `tools/gen_assets.py` from the
chapter files in this folder (`<chapter>.json`). The book must TEACH: a player who has never seen
the mod must understand what each thing *is*, why it matters, and exactly how to use it.

## File format

```json
{
  "chapter": "basics",
  "entries": [
    {
      "id": "power",                      // lowercase, unique in the chapter
      "title": "Energy",
      "icon": "axiomatic:coal_dynamo",    // an item id
      "gate": null,                       // or an advancement id below
      "description": "One line shown on hover in the chapter map",
      "pages": [
        {"type": "text", "title": "Energy", "text": "..."},
        {"type": "spotlight", "item": "axiomatic:coal_dynamo", "title": "Coal Dynamo", "text": "..."},
        {"type": "recipe", "recipes": ["coal_dynamo", "copper_cable"], "text": "optional caption"}
      ]
    }
  ]
}
```

- Entries appear in the chapter map in file order and are linked in a chain in that order.
- `recipe` pages: 1 or 2 recipe ids (axiomatic recipe names: see `src/main/resources/data/axiomatic/recipe/`).
  A caption only fits with ONE recipe.
- `gate`: the entry is hidden until the player earns that advancement. Allowed: null, "zero",
  "certified", "circuit_board", "defined", "proven", "induction", "named", "conjecture", "disaster",
  "prime_core", "prime_forged", "prime_well", "structure", "implemented", "general_recursion".
  Opening-hour material must be ungated.
- Text is Modonomicon Markdown: **bold**, *italics*, lists with "- ", blank line between paragraphs.
  Write underscores plainly (zero_add): the generator escapes them. Item links: [](item://axiomatic:test_bench).
  Entry links: [text](entry://axiomatic:notebook/<chapter>/<entry id>).
- Keep each text page to about 700 characters (long pages split automatically, but short pages read
  better). Use as many pages as the topic needs.

## Style

- Second person, plain language, for a curious player who is NOT a mathematician.
- For every machine: first what it IS and why you want it (one or two sentences), then **How to use**
  with the slots named exactly as their hover hints say (the slot hint texts are the
  `"slot.axiomatic.*"` strings in `tools/gen_assets.py`) and buttons named exactly as on screen
  (`"button.axiomatic.*"`), then a concrete **Example** with real items and the exact result, then
  **Watch out** for common mistakes (status messages the player will see: `"status.axiomatic.*"`).
- For every concept (numeral, circuit, statement, proof, certificate, hypothesis, conjecture...):
  what it is, how it looks in game (item, tooltip), how you get one, what you do with it.
- Explain symbols the first time they appear (∀ for all, ∃ there is, → implies, ∧ and, ¬ not,
  ≤, |, S(n) = n + 1).
- Accuracy over flourish: every claim must match the code. Read the machine class, its
  `MachineLayout`, the lang strings, and the game tests (`src/main/java/.../gametest/`) that use it.
  Game tests show the exact working sequences; follow them for worked examples.
- Mention costs (energy) where they matter. Don't invent features. If unsure, check the code.
